API de Sumcoin Explorer REST + WebSocket

Crea monederos, paneles, servicios de pago, herramientas de monitorización y aplicaciones blockchain utilizando la API pública de Sumcoin Explorer.

URL base

https://sumcoin.space/api

Formato de respuesta

JSON

Autenticación

No se necesita una clave API

La API REST permite consultar bloques, transacciones, saldos de direcciones, salidas no gastadas, estado de sincronización, tipos de cambio y otros datos en vivo de la red Sumcoin.

Socket.IO también está disponible para aplicaciones que necesiten recibir notificaciones en tiempo real cuando llegan nuevos bloques o transacciones.

API pública: las solicitudes pueden estar sujetas a límites de frecuencia. Las aplicaciones deberían almacenar en caché las respuestas cuando sea razonable y evitar consultas innecesariamente frecuentes.
Inicio rápido

1. Abre un endpoint en el navegador

Los endpoints GET pueden abrirse directamente en un navegador.

Probar información del nodo Probar últimos bloques Probar estado de sincronización

2. cURL

curl 'https://sumcoin.space/api/status?q=getInfo'

3. JavaScript

fetch('https://sumcoin.space/api/status?q=getInfo')
  .then(function(response) {
    return response.json();
  })
  .then(function(data) {
    console.log(data);
  });

4. Python

import requests

data = requests.get(
    'https://sumcoin.space/api/status?q=getInfo'
).json()

print(data)
Bloques

Obtener el hash desde una altura

Convierte una altura numérica de bloque en el hash correspondiente. 

GET /api/block-index/<height>

Ejemplo

curl 'https://sumcoin.space/api/block-index/0'

Respuesta

{
  "blockHash": "..."
}

Probar altura 0

Detalles de un bloque

GET /api/block/<blockHash>

Devuelve información decodificada del bloque, incluyendo altura, hash, fecha y hora, transacciones y otros metadatos. 

curl 'https://sumcoin.space/api/block/BLOCK_HASH'

Bloque sin procesar

GET /api/rawblock/<blockHash>

Devuelve los datos serializados del bloque en hexadecimal. Está pensado para aplicaciones que necesitan la representación original codificada del bloque.

Resumen de bloques

GET /api/blocks?limit=10

Devuelve una colección de los bloques recientes.

Por fecha

GET /api/blocks?limit=10&blockDate=2026-09-27

Probar últimos 5 bloques

Transacciones

Detalles de una transacción

GET /api/tx/<txid>

Devuelve la transacción decodificada, incluyendo entradas, salidas, confirmaciones, bloque y valores. 

curl 'https://sumcoin.space/api/tx/YOUR_TXID'

Transacción sin procesar

GET /api/rawtx/<txid>

Respuesta

{
  "rawtx": "01000000..."
}

Transacciones de un bloque

GET /api/txs?block=<blockHash>&pageNum=0

Devuelve las transacciones asociadas con el bloque especificado. Los resultados están paginados.

Transacciones de una dirección

GET /api/txs?address=<address>&pageNum=0

Devuelve las transacciones relacionadas con una dirección Sumcoin.

Transmitir una transacción firmada

POST /api/tx/send

Envía a la red Sumcoin una transacción sin procesar que ya fue creada y firmada.

Este endpoint no crea la transacción, selecciona entradas, calcula cambio ni firma nada.

cURL

curl -X POST \
  'https://sumcoin.space/api/tx/send' \
  --data-urlencode 'rawtx=SIGNED_TRANSACTION_HEX'

Respuesta correcta

{
  "txid": "TRANSACTION_ID"
}

Direcciones

Resumen de una dirección

GET /api/addr/<address>

Devuelve saldos, número de transacciones e historial relacionado con una dirección.

Sin lista de transacciones

GET /api/addr/<address>?noTxList=1

Historial paginado

GET /api/addr/<address>?from=0&to=20

Valores individuales de una dirección

Saldo GET /api/addr/<address>/balance
Total recibido GET /api/addr/<address>/totalReceived
Total enviado GET /api/addr/<address>/totalSent
Saldo sin confirmar GET /api/addr/<address>/unconfirmedBalance
Los endpoints de saldo individual pueden devolver el valor entero de la unidad mínima utilizado internamente por la API.

Salidas no gastadas (UTXO)

GET /api/addr/<address>/utxo

Devuelve las salidas actualmente no gastadas pertenecientes a la dirección. Los monederos pueden utilizarlas al construir nuevas transacciones.

Respuesta típica

[
  {
    "address": "...",
    "txid": "...",
    "vout": 0,
    "scriptPubKey": "...",
    "amount": 1.250000,
    "satoshis": 1250000,
    "confirmations": 42
  }
]

UTXO para varias direcciones

GET

GET /api/addrs/ADDRESS1,ADDRESS2/utxo

POST

POST /api/addrs/utxo

addrs=ADDRESS1,ADDRESS2

Transacciones para varias direcciones

GET /api/addrs/ADDRESS1,ADDRESS2/txs?from=0&to=20

Controles opcionales:

to Último elemento del rango

Verificación criptográfica de mensajes

Las direcciones Sumcoin pueden utilizarse para firmar criptográficamente texto arbitrario. Una firma válida demuestra que quien firmó controlaba la clave privada correspondiente a la dirección indicada. 

GET  /api/messages/verify
POST /api/messages/verify

Valores necesarios:

  • address — dirección Sumcoin
  • signature — firma criptográfica
  • message — mensaje original exacto

Ejemplo cURL

curl -X POST \
  'https://sumcoin.space/api/messages/verify' \
  --data-urlencode 'address=SUMCOIN_ADDRESS' \
  --data-urlencode 'signature=BASE64_SIGNATURE' \
  --data-urlencode 'message=Controlo esta dirección Sumcoin.'

Respuesta

{
  "result": true
}

Abrir la herramienta de verificación de mensajes

Mensajes firmados y datos en la blockchain

Un mensaje firmado normal permanece fuera de la blockchain. Firmarlo no crea una transacción ni almacena el mensaje permanentemente.

Sumcoin Core también admite salidas de datos OP_RETURN. Una aplicación puede utilizar una transacción independiente para registrar una pequeña cantidad de datos, una firma o un hash criptográfico.

Son dos operaciones diferentes:
la firma de mensajes demuestra control de una clave privada; una transacción en la blockchain proporciona un registro público confirmado y permanente.
Los datos almacenados en una blockchain son públicos y prácticamente permanentes. Nunca almacenes claves privadas, contraseñas ni información confidencial.
API WebSocket en vivo

Socket.IO proporciona notificaciones blockchain en tiempo real sin que una aplicación tenga que consultar constantemente la API REST.

Eventos disponibles

tx Nueva transacción. Suscríbete a la sala inv.
block Nuevo bloque. Suscríbete a la sala inv.
<address> Actividad de una dirección concreta. Suscríbete a esa dirección como sala.
status Progreso de sincronización. Suscríbete a la sala sync.

Escuchar nuevos bloques y transacciones

<script src="https://sumcoin.space/socket.io/socket.io.js"></script>

<script>
var socket = io('https://sumcoin.space');

socket.on('connect', function() {

  socket.emit('subscribe', 'inv');

  socket.on('block', function(block) {
    console.log('Nuevo bloque:', block);
  });

  socket.on('tx', function(tx) {
    console.log('Nueva transacción:', tx);
  });

});
</script>

Vigilar una dirección Sumcoin

var address = 'YOUR_SUMCOIN_ADDRESS';
var socket = io('https://sumcoin.space');

socket.on('connect', function() {

  socket.emit('subscribe', address);

  socket.on(address, function(tx) {
    console.log('Actividad de la dirección:', tx);
  });

});

Vigilar la sincronización

var socket = io('https://sumcoin.space');

socket.on('connect', function() {

  socket.emit('subscribe', 'sync');

  socket.on('status', function(status) {
    console.log(status);
  });

});
Respuestas, errores y notas de integración

CORS

La API pública permite solicitudes desde aplicaciones web alojadas en otros dominios mediante encabezados de acceso entre orígenes.

Respuesta 404

{
  "status": 404,
  "url": "/api/example",
  "error": "Not found"
}

Límites de solicitudes

La API incluye soporte para limitar la frecuencia de solicitudes. Las aplicaciones de producción deberían poder manejar limitación temporal, fallos de red y respuestas distintas de HTTP 200.

Valores y confirmaciones

Dependiendo del endpoint, los valores pueden aparecer como cantidades decimales de SUM o como enteros en la unidad mínima. Utiliza siempre el campo documentado por cada endpoint.
