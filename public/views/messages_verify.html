What does this prove?

A Sumcoin wallet can use the private key belonging to an address to create a cryptographic signature for any text.

If this page reports that the signature is valid, it proves:

Whoever created that signature controlled the private key for the stated Sumcoin address when the signature was made.

It does not reveal the private key.

This is not a messaging service

Verifying a signed message does not send a message to another person and does not automatically put anything on the blockchain.

It does not:

  • send a text or chat message
  • create a Sumcoin transaction
  • spend Sumcoin
  • charge a network fee
  • publish the message to the blockchain
  • reveal the signer's private key
Example

A person might sign:

I control this Sumcoin address.
Verification requested by example.com.
Date: 2026-09-27
Nonce: 7F42A91C

Their wallet returns a cryptographic signature. They can then give someone: 

Address:
SUMCOIN_ADDRESS

Message:
I control this Sumcoin address.
Verification requested by example.com.
Date: 2026-09-27
Nonce: 7F42A91C

Signature:
BASE64_SIGNATURE

Anyone can use this page to verify those three values without needing the private key.

How do I create a signed message?

Use a trusted Sumcoin wallet that controls the address. The private key should remain in that wallet.

Sumcoin Core supports the signmessage RPC. 

sumcoin-cli signmessage \
  "YOUR_SUMCOIN_ADDRESS" \
  "Your exact message"

For an encrypted wallet, it may need to be unlocked before signing.

Never paste your private key into this explorer. Only the address, message and resulting signature are needed for verification.
Can a signed message be put on the Sumcoin blockchain?

Yes, but that is a separate operation.

The signature created above is normally off-chain. Sumcoin Core also supports data-carrier / OP_RETURN transaction outputs, which applications can use to commit a small amount of arbitrary data to a transaction.

An application could therefore:

  1. create a message,
  2. sign it with a Sumcoin address,
  3. verify the signature, and then
  4. store a short message, signature, or cryptographic hash in a separate on-chain transaction.

That can produce a permanent public record showing that a particular data commitment existed in a confirmed Sumcoin block.

On-chain data is public and effectively permanent. Never put private keys, passwords, personal secrets or other sensitive information into blockchain data.
What does verification not prove?

A valid signature proves control of the private key associated with the address. By itself, it does not prove the signer's real-world legal identity.

It also does not automatically prove when a message was signed. For current-control proofs, include a date, purpose and unique nonce in the text before signing.
