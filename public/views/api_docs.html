Sumcoin Explorer API REST + WebSocket

Build wallets, dashboards, payment services, monitoring tools and blockchain applications using the public Sumcoin Explorer API.

Base URL

https://sumcoin.space/api

Response format

JSON

Authentication

No API key required

The REST API lets applications retrieve blocks, transactions, address balances, unspent outputs, synchronization information, currency rates and other live Sumcoin network data.

Socket.IO is also available for applications that need live notifications when blocks or transactions arrive.

Public API: Requests may be rate limited. Applications should cache responses where practical and avoid unnecessary high-frequency polling.
Quick Start

1. Open an endpoint in your browser

Any GET endpoint can be opened directly.

Try Node Information Try Latest Blocks Try Sync Status

2. cURL

curl 'https://sumcoin.space/api/status?q=getInfo'

3. JavaScript

fetch('https://sumcoin.space/api/status?q=getInfo')
  .then(function(response) {
    return response.json();
  })
  .then(function(data) {
    console.log(data);
  });

4. Python

import requests

data = requests.get(
    'https://sumcoin.space/api/status?q=getInfo'
).json()

print(data)
Blocks

Use these endpoints to locate blocks, retrieve block details, inspect raw block data or browse blocks by date.

Block hash from height

Converts a numeric block height into its block hash. 

GET /api/block-index/<height>

Example

curl 'https://sumcoin.space/api/block-index/0'

Response

{
  "blockHash": "..."
}

Try block height 0

Block details

GET /api/block/<blockHash>

Returns decoded information about a block including its height, hash, timestamp, transaction information and related metadata. 

curl 'https://sumcoin.space/api/block/BLOCK_HASH'

Raw block

GET /api/rawblock/<blockHash>

Returns the serialized block data in hexadecimal form. This is intended for applications that need the original encoded block rather than the decoded explorer representation.

Block summaries

GET /api/blocks?limit=10

Returns a collection of recent block summaries.

By date

GET /api/blocks?limit=10&blockDate=2026-09-27

Try latest 5 blocks

Transactions

Transaction details

GET /api/tx/<txid>

Returns the decoded transaction including inputs, outputs, confirmation information, block information and values. 

curl 'https://sumcoin.space/api/tx/YOUR_TXID'

Raw transaction

GET /api/rawtx/<txid>

Response

{
  "rawtx": "01000000..."
}

Transactions in a block

GET /api/txs?block=<blockHash>&pageNum=0

Returns transactions associated with the specified block. Results are paginated.

Transactions for an address

GET /api/txs?address=<address>&pageNum=0

Returns transactions associated with a Sumcoin address.

Broadcast a signed transaction

POST /api/tx/send

Broadcasts an already-created and already-signed raw transaction to the Sumcoin network.

This endpoint does not create a transaction, choose inputs, calculate change or sign anything.

cURL

curl -X POST \
  'https://sumcoin.space/api/tx/send' \
  --data-urlencode 'rawtx=SIGNED_TRANSACTION_HEX'

Successful response

{
  "txid": "TRANSACTION_ID"
}

Open the Broadcast Transaction tool

Addresses

Address summary

GET /api/addr/<address>

Returns balances, transaction counts and transaction history associated with an address.

Without transaction list

GET /api/addr/<address>?noTxList=1

Paginated history

GET /api/addr/<address>?from=0&to=20

Individual address values

Balance GET /api/addr/<address>/balance
Total received GET /api/addr/<address>/totalReceived
Total sent GET /api/addr/<address>/totalSent
Unconfirmed balance GET /api/addr/<address>/unconfirmedBalance
The single-value balance endpoints return the raw smallest-unit integer value used internally by the API.

Unspent transaction outputs (UTXOs)

GET /api/addr/<address>/utxo

Returns currently unspent outputs belonging to the address. Wallets can use these when constructing new transactions.

Typical response

[
  {
    "address": "...",
    "txid": "...",
    "vout": 0,
    "scriptPubKey": "...",
    "amount": 1.250000,
    "satoshis": 1250000,
    "confirmations": 42
  }
]

UTXOs for multiple addresses

GET

GET /api/addrs/ADDRESS1,ADDRESS2/utxo

POST

POST /api/addrs/utxo

addrs=ADDRESS1,ADDRESS2

Transactions for multiple addresses

GET /api/addrs/ADDRESS1,ADDRESS2/txs?from=0&to=20

Optional response controls:

from First history item to return
to Last history item range
noAsm=1 Omit script assembly
noScriptSig=1 Omit input scriptSig data
noSpent=1 Omit output spent information

Cryptographic Message Verification

Sumcoin addresses can be used to cryptographically sign arbitrary text. A valid signature proves that the signer controlled the private key for the stated Sumcoin address when the signature was created. 

GET  /api/messages/verify
POST /api/messages/verify

Required values:

  • address — Sumcoin address claiming authorship
  • signature — cryptographic message signature
  • message — exact original message

cURL example

curl -X POST \
  'https://sumcoin.space/api/messages/verify' \
  --data-urlencode 'address=SUMCOIN_ADDRESS' \
  --data-urlencode 'signature=BASE64_SIGNATURE' \
  --data-urlencode 'message=I control this Sumcoin address.'

Response

{
  "result": true
}

Open the Verify Signed Message tool

Signed Messages vs. On-chain Messages

A normal signed message is off-chain. Signing it does not create a transaction and does not permanently store the message anywhere.

Sumcoin Core also supports data-carrier / OP_RETURN outputs. That makes it possible for applications to separately commit a short message, signature, hash or other small payload inside a Sumcoin transaction.

These are two different operations:
message signing proves control of a private key; an on-chain transaction provides public, timestamped blockchain storage. An application can combine the two.

A possible application flow is:

  1. User creates a short statement.
  2. User signs that statement with a Sumcoin address.
  3. The signature is verified.
  4. The application places the message, signature, or preferably a compact cryptographic hash into a data-carrying transaction.
  5. Once confirmed, the blockchain provides a permanent public record that the commitment existed.
Blockchain data is public and effectively permanent. Do not place passwords, private keys, personal secrets or other sensitive information into an on-chain data field.
Live WebSocket API

Socket.IO provides live blockchain notifications without requiring an application to repeatedly poll REST endpoints.

Available event types

tx New transaction received. Subscribe to the inv room.
block New block received. Subscribe to the inv room.
<address> Transaction activity involving a particular address. Subscribe to that address as the room.
status Explorer synchronization progress. Subscribe to the sync room.

Listen for new blocks and transactions

<script src="https://sumcoin.space/socket.io/socket.io.js"></script>

<script>
var socket = io('https://sumcoin.space');

socket.on('connect', function() {

  socket.emit('subscribe', 'inv');

  socket.on('block', function(block) {
    console.log('New block:', block);
  });

  socket.on('tx', function(tx) {
    console.log('New transaction:', tx);
  });

});
</script>

Watch a Sumcoin address

var address = 'YOUR_SUMCOIN_ADDRESS';
var socket = io('https://sumcoin.space');

socket.on('connect', function() {

  socket.emit('subscribe', address);

  socket.on(address, function(tx) {
    console.log('Address activity:', tx);
  });

});

Watch explorer synchronization

var socket = io('https://sumcoin.space');

socket.on('connect', function() {

  socket.emit('subscribe', 'sync');

  socket.on('status', function(status) {
    console.log(status);
  });

});
Responses, Errors & Integration Notes

CORS

The public API sends cross-origin headers so browser applications can request API data from another website.

404 response

{
  "status": 404,
  "url": "/api/example",
  "error": "Not found"
}

Rate limits

The API contains request-rate limiting support. Production applications should be designed to handle temporary throttling, network failures and non-200 responses gracefully.

Values and confirmations

Blockchain values can appear both as decimal SUM amounts and as raw smallest-unit integers depending on the endpoint. Applications should use the field documented by the endpoint rather than assuming every numeric response uses the same unit.
